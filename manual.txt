La URL decide qué vista atiende la petición ( urls.py ).
La vista es una función de Python que decide qué hacer ( views.py ).
El servicio habla con la base de datos ( services.py ). Esta capa la agregamos nosotros para que las vistas
queden limpias.
La plantilla es el HTML que se le devuelve al usuario ( templates/ ).
Firebase es una plataforma de Google. Usaremos dos de sus servicios:
Servicio Para qué lo usamos Equivalente que ya conoces
Authentication Guardar usuarios y verificar correo y
contraseña
La tabla de usuarios de cualquier sitio web
Firestore Guardar libros, préstamos y perfiles Una base de datos, pero de documentos en lugar de
tablas
Firestore organiza la información en colecciones (como carpetas) que contienen documentos (como fichas). Cada
documento es parecido a un diccionario de Python:
users / {uid}
email "ana@..."
name "Ana Torres"
role "librarian"
created_at fecha
books / {id}
title "Clean Code"
author "R. Martin"
category "Programación"
copies_total 3
copies_available 2
loans / {id}
book_id →  books
user_id →  users
book_title copia
status "active"
loaned_at fecha
due_at +14 días
Cada caja es una colección y muestra un documento de ejemplo.
Los campos con →  apuntan al documento de otra colección.
Figura: las tres colecciones de Firestore
Nuestro servidor Python se conecta a Firebase de dos maneras:
Admin SDK (librería firebase-admin ): acceso total a Firestore y a la lista de usuarios, usando una llave
privada. Solo vive en el servidor.
API REST (librería requests ): la única forma de comprobar una contraseña. Le enviamos correo y contraseña a
Google y nos responde si son correctos.

2. Pulsa Crear un proyecto (Create a project). Ponle un nombre, por ejemplo biblioteca-clase . Cuando

Elegimos modo producción, que bloquea el acceso desde navegadores. No nos afecta: nuestro servidor usa la

nuestro servidor Django.

1.8 Organizar el proyecto por features
La mayoría de tutoriales organizan el código por tipo de archivo: una carpeta con todas las vistas, otra con todas
las plantillas… Cuando el proyecto crece, para cambiar algo del préstamo de libros tienes que abrir cinco carpetas
distintas.
Nosotros usaremos arquitectura por features (feature-driven): todo lo que pertenece a una funcionalidad vive
junto, en una sola carpeta.
E J E M P LO
biblioteca/
├── config/              ←  configuración global del proyecto
├── core/                ←  lo compartido (conexión a Firebase, base.html, permisos…)
└── features/
├── accounts/        ←  login, registro y logout
├── books/           ←  catálogo de libros
├── loans/           ←  prestar, devolver y cancelar
├── dashboard/       ←  estadísticas y gráficas

def login_required(view):
"""Exige que haya un usuario en la sesión."""
@wraps(view)
def wrapper(request, *args, **kwargs):
if not request.session.get('user'):
return redirect_to_login(request.get_full_path(), reverse('accounts:login'))
return view(request, *args, **kwargs)
return wrapper
def role_required(role):
"""Exige estar logueado y tener el rol indicado."""
def decorator(view):
@wraps(view)
@login_required
def wrapper(request, *args, **kwargs):
if request.session['user']['role'] != role:
messages.error(request, 'No tienes permiso para ver esa página.')
return redirect('books:list')
return view(request, *args, **kwargs)
return wrapper
return decorator
librarian_required = role_required(LIBRARIAN)
student_required = role_required(STUDENT)

"""Usuarios: autenticación con Firebase Auth y perfil/rol en Firestore."""
import requests
from django.conf import settings
from firebase_admin import auth, firestore
from google.cloud.firestore_v1.base_query import FieldFilter
from core.firebase import get_db
SIGN_IN_URL = 'https://identitytoolkit.googleapis.com/v1/accounts:signInWithPassword'
# Mensajes de error de la REST API de Firebase traducidos
AUTH_ERRORS = {
'INVALID_LOGIN_CREDENTIALS': 'Correo o contraseña incorrectos.',
'INVALID_PASSWORD': 'Correo o contraseña incorrectos.',
'EMAIL_NOT_FOUND': 'Correo o contraseña incorrectos.',
'USER_DISABLED': 'Esta cuenta está deshabilitada.',
'TOO_MANY_ATTEMPTS_TRY_LATER': 'Demasiados intentos. Intenta más tarde.',
}
class AuthError(Exception):
"""Error de autenticación con un mensaje listo para mostrar al usuario."""
def sign_in(email, password):
"""Valida correo y contraseña contra Firebase Auth y devuelve los datos de sesión.
La contraseña solo se puede verificar con la REST API (el Admin SDK no puede),
por eso usamos `requests` aquí.
"""
response = requests.post(
SIGN_IN_URL,
params={'key': settings.FIREBASE_WEB_API_KEY},
json={'email': email, 'password': password, 'returnSecureToken': True},
timeout=10,
)
if response.status_code != 200:
code = response.json().get('error', {}).get('message', '')
raise AuthError(AUTH_ERRORS.get(code.split(' ')[0], 'No se pudo iniciar sesión.'))
# Verificamos el token con el Admin SDK en lugar de confiar a ciegas en la respuesta.
get_db()
decoded = auth.verify_id_token(response.json()['idToken'], clock_skew_seconds=10)
return get_session_user(decoded['uid'], email, decoded.get('name', ''))

def get_session_user(uid, email, name=''):
"""Lee el rol del usuario en Firestore (lo crea como estudiante si no existe)."""
ref = get_db().collection('users').document(uid)
snapshot = ref.get()
if snapshot.exists:
data = snapshot.to_dict()
else:
data = {'email': email, 'name': name or email.split('@')[0], 'role': 'student'}
ref.set({**data, 'created_at': firestore.SERVER_TIMESTAMP})
return {'uid': uid, 'email': data['email'], 'name': data['name'], 'role': data['role']}
def create_user(name, email, password, role):
"""Crea la cuenta en Firebase Auth y su perfil (con el rol) en Firestore."""
get_db()
try:
user = auth.create_user(email=email, password=password, display_name=name)
except auth.EmailAlreadyExistsError:
raise AuthError('Ya existe una cuenta con ese correo.')
except ValueError as exc:
raise AuthError(str(exc))
get_db().collection('users').document(user.uid).set(
{'email': email, 'name': name, 'role': role, 'created_at': firestore.SERVER_TIMESTAMP}
)
return user.uid
def register_student(name, email, password):
"""Registro público: siempre crea un estudiante."""
return create_user(name, email, password, role='student')
def list_students():
"""Perfiles con rol estudiante: [{'uid', 'email', 'name', ...}]."""
docs = get_db().collection('users').where(filter=FieldFilter('role', '==', 'student')).stream()
return [{'uid': d.id, **d.to_dict()} for d in docs]
¿Por qué el rol no va en Authentication?
Authentication solo sabe de correos y contraseñas. El rol ( student  o librarian ) lo guardamos en nuestro
propio documento users/{uid}  en Firestore. Así podemos cambiarlo cuando queramos sin tocar la cuenta.

from django.contrib import messages
from django.shortcuts import redirect, render
from django.views.decorators.http import require_POST
from . import services
from .forms import LoginForm, RegisterForm
from .services import AuthError
def login_view(request):
if request.session.get('user'):
return redirect('core:home')
form = LoginForm(request.POST or None)
if request.method == 'POST' and form.is_valid():
try:
user = services.sign_in(form.cleaned_data['email'], form.cleaned_data['password'])
except AuthError as exc:
form.add_error(None, str(exc))
else:
request.session.cycle_key()
request.session['user'] = user
messages.success(request, f"¡Hola, {user['name']}!")
next_url = request.GET.get('next', '')
return redirect(next_url if next_url.startswith('/') else 'core:home')
return render(request, 'accounts/login.html', {'form': form})
def register_view(request):
form = RegisterForm(request.POST or None)
if request.method == 'POST' and form.is_valid():
try:
services.register_student(
form.cleaned_data['name'], form.cleaned_data['email'], form.cleaned_data['password']
)
except AuthError as exc:
form.add_error(None, str(exc))
else:
messages.success(request, 'Cuenta creada. Ya puedes iniciar sesión.')
return redirect('accounts:login')
return render(request, 'accounts/register.html', {'form': form})
@require_POST
def logout_view(request):
request.session.flush()
return redirect('accounts:login')

class Command(BaseCommand):
help = 'Crea un usuario en Firebase Auth con su rol en Firestore.'
def add_arguments(self, parser):
parser.add_argument('email')
parser.add_argument('name', help='Nombre completo (entre comillas si tiene espacios).')
parser.add_argument('--role', choices=['student', 'librarian'], default='student')
def handle(self, *args, **options):
password = getpass('Contraseña (mínimo 6 caracteres): ')
if getpass('Repite la contraseña: ') != password:
raise CommandError('Las contraseñas no coinciden.')
try:
services.create_user(options['name'], options['email'], password, options['role'])
except services.AuthError as exc:
raise CommandError(str(exc))
self.stdout.write(self.style.SUCCESS(f"Usuario {options['email']} creado con rol {options['role']}."))

2.4 Paginación reutilizable en core
Con 24 libros (y más adelante 90 préstamos) una lista infinita es incómoda. Paginar es repartir los elementos en
páginas de 10. Django ya trae un Paginator ; nosotros lo envolvemos en una función que usarán todas las
features.
paginate(request, items)  devuelve un diccionario con tres cosas que la plantilla necesita: la página actual
( page_obj ), la lista de números a mostrar ( page_range , con …  cuando hay muchas) y el querystring , que
conserva los filtros ( ?q=python ) al cambiar de página.
core/pagination.py ARCHIVO NUEVO
"""Paginación sencilla de listas en memoria (los datos de este proyecto son pequeños)."""
from django.conf import settings
from django.core.paginator import Paginator
def paginate(request, items, per_page=None):
"""Devuelve el contexto de paginación para los templates.
- page_obj: la página actual (sus elementos, número, si hay anterior/siguiente…)
- page_range: números a mostrar, con "…" cuando hay muchas páginas
- querystring: los filtros actuales (q, status…) sin `page`, para conservarlos en los enlaces
"""
paginator = Paginator(items, per_page or settings.PAGE_SIZE)
page_obj = paginator.get_page(request.GET.get('page'))
params = request.GET.copy()
params.pop('page', None)
return {
'page_obj': page_obj,
'page_range': list(paginator.get_elided_page_range(page_obj.number, on_each_side=1, on_ends=1)),
'querystring': params.urlencode(),
}

services.py  · el catálogo en Firestore
Todo lo que toca la colección books  está aquí, y solo aquí. Las vistas nunca hablan directo con Firestore.
Función Qué hace
books_collection() Devuelve la colección books  (la usará loans  en la clase 3)
list_books(query, category) Lista ordenada por título, con filtro opcional de texto y categoría
list_categories() Las categorías existentes (para el desplegable)
get_book(book_id) Un libro por su identificador, o None
create_book(...) Crea el libro con todas sus copias disponibles
update_book(...) Edita el libro y recalcula las copias disponibles
delete_book(book_id) Elimina el libro, solo si ninguna copia está prestada
Dos reglas de negocio viven aquí: no puedes bajar las copias totales por debajo de las que están prestadas, y no
puedes eliminar un libro con copias prestadas. Ambas lanzan BookError  con un mensaje listo para mostrar.
Por qué filtramos en Python
Firestore no puede buscar "títulos que contengan 'pyth'". Como nuestro catálogo es pequeño, traemos
todos los libros y filtramos con Python ( list_books ). Para catálogos de miles de libros se usaría un buscador
especializado.
features/books/services.py ARCHIVO NUEVO
"""Catálogo de libros (colección `books` en Firestore)."""
from core.firebase import get_db
class BookError(Exception):
"""Regla de negocio incumplida al modificar un libro."""
def books_collection():
return get_db().collection('books')
def list_books(query='', category=''):
"""Lista libros ordenados por título; filtra por texto y categoría en Python."""
books = [{'id': d.id, **d.to_dict()} for d in books_collection().stream()]
query = query.strip().lower()
if query:
books = [b for b in books if query in b['title'].lower() or query in b['author'].lower()]
if category:
books = [b for b in books if b['category'] == category]
return sorted(books, key=lambda b: b['title'].lower())
def list_categories():
return sorted({d.to_dict()['category'] for d in books_collection().stream()})

def get_book(book_id):
snapshot = books_collection().document(book_id).get()
return {'id': snapshot.id, **snapshot.to_dict()} if snapshot.exists else None
def create_book(title, author, category, isbn, copies):
ref = books_collection().document()
ref.set({
'title': title, 'author': author, 'category': category, 'isbn': isbn,
'copies_total': copies, 'copies_available': copies,
})
return ref.id
def update_book(book_id, title, author, category, isbn, copies):
"""Edita un libro; ajusta las copias disponibles según el nuevo total."""
book = get_book(book_id)
if book is None:
raise BookError('El libro no existe.')
on_loan = book['copies_total'] - book['copies_available']
if copies < on_loan:
raise BookError(f'No puedes bajar a {copies} copias: hay {on_loan} prestadas.')
books_collection().document(book_id).update({
'title': title, 'author': author, 'category': category, 'isbn': isbn,
'copies_total': copies, 'copies_available': copies - on_loan,
})
def delete_book(book_id):
"""Elimina un libro. Si hay copias prestadas (disponibles < totales) no se puede."""
book = get_book(book_id)
if book is None:
raise BookError('El libro no existe.')
if book['copies_available'] < book['copies_total']:
raise BookError('No se puede eliminar: tiene préstamos activos.')
books_collection().document(book_id).delete()

@librarian_required
def book_create(request):
form = BookForm(request.POST or None)
if request.method == 'POST' and form.is_valid():
d = form.cleaned_data
services.create_book(d['title'], d['author'], d['category'], d['isbn'], d['copies'])
messages.success(request, 'Libro creado.')
return redirect('books:list')
return render(request, 'books/form.html', {'form': form, 'title': 'Nuevo libro'})
@librarian_required
def book_edit(request, book_id):
book = services.get_book(book_id)
if book is None:
messages.error(request, 'El libro no existe.')
return redirect('books:list')
form = BookForm(request.POST or None, initial={
'title': book['title'], 'author': book['author'], 'category': book['category'],
'isbn': book['isbn'], 'copies': book['copies_total'],
})
if request.method == 'POST' and form.is_valid():
d = form.cleaned_data
try:
services.update_book(book_id, d['title'], d['author'], d['category'], d['isbn'], d['copies'])
except BookError as exc:
form.add_error('copies', str(exc))
else:
messages.success(request, 'Libro actualizado.')
return redirect('books:list')
return render(request, 'books/form.html', {'form': form, 'title': 'Editar libro'})

2.8 El seeder: datos de prueba
Para probar la paginación, las gráficas y los préstamos necesitamos datos, y escribirlos a mano sería eterno. Un
seeder (sembrador) es un script que crea datos de ejemplo. El nuestro es un comando de Django: python
manage.py seed .
Qué hace, en orden:
1. Lee los estudiantes que existen en Firestore (los que creaste en la clase 1). Si no hay ninguno, se detiene con
un mensaje.
2. Borra los libros y préstamos actuales (los usuarios no se tocan).
3. Crea 24 libros de varias categorías con 2 a 5 copias.
4. Genera 90 préstamos repartidos en los últimos 6 meses: los viejos casi siempre están devueltos, algunos
cancelados, y los recientes suelen estar activos. Los más atrasados quedan vencidos.
5. Respeta las reglas: nunca hay más préstamos activos que copias, y ningún estudiante pasa de 3 activos. Al final
calcula copies_available  de cada libro.
6. Escribe todo en Firestore con un lote ( batch ), que guarda varios documentos en una sola operación.
Usa random.seed(42) , así que cada ejecución genera los mismos datos. Eso es útil para que tus resultados se
parezcan a los de esta guía.

books.append({

def _generate_loans(self, books, students):
"""Genera el historial en memoria respetando stock y límite por estudiante."""
now = timezone.now()
# Libros populares: algunos pesan más para que el "top" sea interesante
weights = [random.choice([1, 1, 2, 3, 6]) for _ in books]
loans = []
active_by_book, active_by_student = Counter(), Counter()
for _ in range(LOANS_TO_CREATE):
book = random.choices(books, weights)[0]
student = random.choice(students)
age_days = random.randint(0, MONTHS_BACK * 30)
loaned_at = now - timedelta(days=age_days, hours=random.randint(0, 10))
due_at = loaned_at + timedelta(days=settings.LOAN_DAYS)
roll = random.random()
if age_days < settings.LOAN_DAYS + 7:
status = 'active' if roll < 0.6 else 'returned'
else:
status = 'returned' if roll < 0.85 else ('cancelled' if roll < 0.95 else 'active')

3.3 rules.py : las reglas como funciones puras
Una función pura recibe datos y devuelve un resultado (o lanza un error) sin tocar ninguna base de datos. Poner
las reglas en funciones puras tiene una gran ventaja: se pueden probar en milisegundos, sin Firebase ni internet.

"""Reglas de negocio de los préstamos como funciones puras (sin Firestore).
Los servicios leen los datos dentro de una transacción y llaman a estas funciones
para decidir si la operación es válida. Así las reglas se pueden probar sin base de datos.
"""
from django.conf import settings
ACTIVE, RETURNED, CANCELLED = 'active', 'returned', 'cancelled'
class LoanError(Exception):
"""Regla de negocio incumplida; el mensaje se muestra al usuario."""
def check_can_borrow(book, book_id, active_loans):
"""`book`: dict del libro (o None). `active_loans`: préstamos activos del estudiante."""
if book is None:
raise LoanError('El libro no existe.')
if book['copies_available'] < 1:
raise LoanError('No hay copias disponibles de este libro.')
if len(active_loans) >= settings.MAX_ACTIVE_LOANS:
raise LoanError(f'Ya tienes {settings.MAX_ACTIVE_LOANS} préstamos activos.')
if any(loan['book_id'] == book_id for loan in active_loans):
raise LoanError('Ya tienes un préstamo activo de este libro.')
def check_can_close(loan, user):
"""Devolver o cancelar: solo el dueño o un bibliotecario, y solo si sigue activo."""
if loan is None:
raise LoanError('El préstamo no existe.')
if user['role'] != 'librarian' and loan['user_id'] != user['uid']:
raise LoanError('Ese préstamo no es tuyo.')
if loan['status'] != ACTIVE:
raise LoanError('Ese préstamo ya no está activo.')
def is_overdue(loan, now):
return loan['status'] == ACTIVE and loan['due_at'] < now

3.4 services.py : transacciones en Firestore
Aquí aparece un problema real: dos estudiantes pulsan Prestar a la vez sobre la última copia de un libro. Si cada
servidor lee "queda 1 copia" y luego escribe, los dos se la llevan y el stock queda en -1.
La solución son las transacciones: Firestore garantiza que todo lo que ocurre dentro de la transacción sea atómico
(todo o nada) y, si otro proceso modificó los datos mientras tanto, repite la transacción. Nuestras operaciones
siguen siempre este patrón:
1. Leer (el libro, los préstamos activos del estudiante).
2. Validar con las funciones puras de rules.py .
3. Escribir (descontar la copia y crear el préstamo).
Detalles que debes notar al leer el código:
@firestore.transactional  convierte la función interna run  en una transacción. Todas las lecturas deben ir
antes que las escrituras.
firestore.Increment(-1)  resta una copia de forma atómica en el servidor, sin leer el valor antes.
_close()  sirve para devolver y cancelar: cambia el estado, guarda la fecha y repone la copia. return_loan  y
cancel_loan  solo le indican cuál de las dos.
list_loans()  agrega el campo calculado overdue  a cada préstamo y los ordena del más reciente al más
antiguo.

def _decorate(doc):

loan['overdue'] = rules.is_overdue(loan, timezone.now())

def list_loans(user_id=None, status=''):
"""Préstamos más recientes primero; opcionalmente de un usuario y/o estado."""
query = _loans()
if user_id:
query = query.where(filter=FieldFilter('user_id', '==', user_id))
loans = [_decorate(d) for d in query.stream()]
if status == 'overdue':
loans = [loan for loan in loans if loan['overdue']]
elif status:
loans = [loan for loan in loans if loan['status'] == status]
return sorted(loans, key=lambda loan: loan['loaned_at'], reverse=True)
def borrow(book_id, user):
"""Presta un libro a `user` (dict de sesión). Valida stock y límites."""

book_ref = books_collection().document(book_id)
loan_ref = _loans().document()

filter=FieldFilter('status', '==', ACTIVE)
)
@firestore.transactional
def run(transaction):

book = snapshot.to_dict() if snapshot.exists else None

rules.check_can_borrow(book, book_id, active)

4.2 stats.py : de datos a números
El dashboard responde preguntas como: ¿cuántos préstamos hay por mes?, ¿qué libros se piden más?, ¿cuántos
están vencidos? Para eso separamos dos cosas:
compute_stats(loans, books)  es una función pura: recibe listas y devuelve un diccionario con los números.
No toca Firestore, así que se prueba fácil.
dashboard_stats()  solo lee los datos de los servicios y se los pasa a la anterior.
Usa collections.Counter , una herramienta de Python que cuenta repeticiones:
Counter(títulos).most_common(8)  devuelve los 8 títulos más frecuentes. last_months()  calcula los últimos 6
meses (cruzando el cambio de año) para que los meses sin préstamos aparezcan con 0.

"""Estadísticas del dashboard.
`compute_stats` es una función pura (recibe listas, devuelve números) y se prueba sin
Firestore. `dashboard_stats` solo lee los datos y se los pasa.
"""
from collections import Counter
from django.utils import timezone
from features.books import services as books_service
from features.loans import services as loans_service
MONTHS_ES = ['ene', 'feb', 'mar', 'abr', 'may', 'jun', 'jul', 'ago', 'sep', 'oct', 'nov', 'dic']
def last_months(count, now):
"""Últimos `count` meses como lista de (año, mes), el más antiguo primero."""
now = timezone.localtime(now)
year, month = now.year, now.month
months = []
for _ in range(count):
months.append((year, month))
month -= 1
if month == 0:
year, month = year - 1, 12
return months[::-1]
def compute_stats(loans, books, now=None, months=6):
now = now or timezone.now()
status_counts = Counter()
for loan in loans:
key = 'overdue' if loan['overdue'] else loan['status']
status_counts[key] += 1
by_month = Counter()
for loan in loans:
local = timezone.localtime(loan['loaned_at'])
by_month[(local.year, local.month)] += 1
month_series = [(f'{MONTHS_ES[m - 1]} {y}', by_month[(y, m)]) for y, m in last_months(months, now)]
return {
'kpis': {
'books': len(books),
'copies_available': sum(b['copies_available'] for b in books),
'loans': len(loans),
'active': status_counts['active'] + status_counts['overdue'],
'overdue': status_counts['overdue'],
},
'status_counts': status_counts,
'month_series': month_series,
'top_books': Counter(loan['book_title'] for loan in loans).most_common(8),
'by_category': Counter(loan['book_category'] for loan in loans).most_common(),
}

4.3 charts.py : gráficas con Plotly
Plotly dibuja gráficas interactivas (con tooltip al pasar el cursor) y las entrega como HTML. Nosotros no
escribimos JavaScript: construimos la figura en Python y la incrustamos en la plantilla.
Decisiones de diseño que vale la pena entender:
Un solo color (azul) para magnitudes como "préstamos por mes". Los colores distintos se reservan para los
estados (rojo = vencido, verde = devuelto, gris = cancelado), así el color siempre significa algo.
Barras horizontales cuando las etiquetas son largas (títulos de libros). Los títulos largos se parten en varias
líneas con textwrap  para dejar espacio a las barras.
_headroom()  agrega un 20 % de espacio sobre la barra más larga para que la etiqueta con su número no se
corte en el borde.
La gráfica de estados llega hasta 100 como mínimo ( max(100, ...) ).
_html()  envuelve cada gráfica en un <div>  con alto fijo. Sin él, Plotly mide 0 de alto y las gráficas se montan
unas sobre otras. Además agrega un pequeño script ( post_script ) que reajusta el tamaño al terminar de
cargar la página, para que ninguna gráfica se desborde de su tarjeta.
La librería plotly.js  (el JavaScript que dibuja) se carga una sola vez por página: solo la primera gráfica lleva
first=True .

4.6 Diseño responsive
Hoy casi la mitad de las visitas web vienen de un celular. Responsive significa que la misma página se adapta al
tamaño de la pantalla. Se logra con tres ideas que ya tienes en el proyecto o vas a agregar:
1. La etiqueta viewport  en base.html : <meta name="viewport" content="width=device-width, initial-
scale=1"> . Sin ella, el celular dibuja la página como si midiera 980 px y la encoge.
2. Anchos flexibles: usamos flex  y grid  en lugar de anchos fijos, para que los elementos se acomoden solos.
